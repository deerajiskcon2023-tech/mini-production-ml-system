## Project overview

This project scores credit-card transactions for potential fraud using a trained scikit-learn pipeline and a FastAPI online inference service. It uses the public credit-card fraud dataset (`creditcard.csv`), containing 284,807 rows, 30 input features, and a highly imbalanced binary target (`Class`). The CSV is intentionally not included in this repository; obtain it from the dataset provider and place it at `data/creditcard.csv`.

## Setup

Python 3.11 is recommended. Create and activate a virtual environment, then install the pinned packages:

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Put the dataset at `data/creditcard.csv`. The expected target column is `Class` (0 = legitimate, 1 = fraud); expected features are `Time`, `V1`–`V28`, and `Amount`.

## Train and evaluate

```bash
python src/train.py --data data/creditcard.csv --artifacts artifacts
```

The training script uses a chronological 60/20/20 partition without shuffling. The Logistic Regression pipeline fits `StandardScaler` only on the training partition and uses balanced class weights. A Histogram Gradient Boosting candidate is also evaluated. Candidate selection uses validation PR-AUC; the decision threshold is selected using validation F1. The test partition is held out for final evaluation. Duplicate rows are counted and reported, not silently discarded.

The saved `fraud_model.joblib`, `model_metadata.json`, and `evaluation_report.json` are regenerated by training. The metrics currently committed in `artifacts/evaluation_report.json` are the recorded run represented by the committed model artifact; rerun training to reproduce them on your local copy of the dataset.

## Run the online API

Start the service from the repository root:

```bash
python -m uvicorn serving.app:app --host 127.0.0.1 --port 8000
```

Open `http://127.0.0.1:8000/docs` for interactive API documentation.

Health check:

```bash
curl http://127.0.0.1:8000/health
```

Example prediction using the included valid sample payload:

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  --data-binary @tests/sample_request.json
```

The API rejects missing/extra fields and negative transaction amounts through Pydantic validation. If the model artifact cannot be loaded, `/health` reports a degraded state and `/predict` returns HTTP 503 rather than inventing a score.

## Benchmark latency

Keep the API running in one terminal, then run:

```bash
python serving/benchmark.py --requests 200 --payload tests/sample_request.json
```

The benchmark warms up the API, measures at least 100 requests, and reports p50/p95/p99 latency and observed requests/second. Results are machine- and environment-dependent; record the output from the computer used for the final submission.

## Drift monitoring

Prepare a reference CSV from training-period features and a recent production/incoming CSV with matching numeric feature names. Then run:

```bash
python monitoring/drift_monitor.py --reference data/reference.csv --current data/current.csv --output artifacts/drift_report.json
```

The script calculates PSI and two-sample Kolmogorov–Smirnov statistics per common numeric feature. PSI >= 0.20 is a warning and PSI >= 0.30 is critical by default; KS p < 0.01 is also a warning. Investigate alerts and verify model quality before retraining; drift alone is not sufficient evidence to deploy a new model.

## Operational monitoring and fallback

Monitor request count, p50/p95/p99 latency, HTTP 4xx/5xx rates, model-load state, input schema violations, feature missingness/ranges, PSI, KS statistics, and delayed-label precision/recall/PR-AUC. Page the owner for sustained p95 latency above the service SLO or elevated 5xx rates. Investigate PSI/KS alerts; initiate a controlled retraining evaluation only when drift is persistent and/or labeled performance degrades. Keep the current champion artifact available for rollback. The API fails closed with HTTP 503 when the model is unavailable and returns explicit validation errors for malformed input.
